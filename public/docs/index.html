Build on CMOSTimer

API 2 runs every enabled plugin in its own dedicated Web Worker. Plugins communicate with the timer through a versioned, asynchronous cmos API and return declarative UI instead of accessing application DOM.

Quick start

Open Settings -> Plugins, add a plugin, paste code, and save it. Top-level await is supported.

await cmos.toast(`API ${cmos.apiVersion}`);

cmos.on('solveAdded', solve => {
  void cmos.toast(`Recorded ${(solve.time / 1000).toFixed(2)}s`);
});

cmos.registerWidget('hello', 'Hello', async () => ({
  type: 'text',
  text: `Session: ${(await cmos.getState()).currentSessionId}`,
  tone: 'accent'
}));

Isolation and security

Default boundary: plugin source runs in a module Worker. It does not receive window, DOM nodes, CMOSTimer objects, or native Tauri/Capacitor bridges. The host accepts only an enumerated RPC protocol and validates registrations, payload sizes, and rendered UI trees.

Not a perfect sandbox: browsers and WebViews can expose worker-local capabilities such as fetch, WebSocket, timers, IndexedDB, and nested workers. An enabled plugin can also change or delete timer data through cmos. Review code before enabling it.

If dedicated module workers are unavailable, CMOSTimer fails closed and marks the plugin unsupported. It does not fall back to page execution. Apache and Tauri configurations restrict Worker origins to 'self'. A deployment that adds script-src must currently retain 'unsafe-eval' for Worker-side plugin compilation. Web, Tauri, and Capacitor support ultimately depends on the installed browser/WebView.

Explicit permissions

Every host capability is denied until granted in the plugin editor. Imported manifests may request permissions, but imports receive no grants automatically.

Async API rule

State, actions, dialogs, storage, and widget refresh cross the worker boundary and return promises. Registration calls and on(...) are synchronous because they stage worker-local callbacks.

const state = await cmos.getState();
await cmos.storage.set('enabled', true);
await cmos.nextScramble();

Cross-boundary values must be structured-cloneable. Requests are limited to 1 MB; UI trees also have depth, node-count, and text limits.

Versioning and packages

cmos.apiVersion reports the semantic API version. A package uses exact major.minor.patch; its major must match and its required minor/patch cannot exceed the app. Imports remain disabled until reviewed.

{
  "format": "cmostimer-plugin",
  "formatVersion": 1,
  "plugin": {
    "id": "example.plugin",
    "name": "Example",
    "version": "1.0.0",
    "description": "An isolated example",
	"apiVersion": "2.1.0",
	"permissions": ["state:read", "ui"],
    "code": "await cmos.toast('Ready')",
    "enabled": false
  }
}

Diagnostics are disabled, loading, active, fallback, error, incompatible, and unsupported.

Sessions and statistics

createSession({ name, scramblerId, tags? }), updateSession(id, { name?, locked?, tags?, scramblerId? }), and deleteSession(id) provide safe session management. getStatistics({ sessionId?, type, size? }) returns count, valid count, total time, current/best values, and best solve ids for SINGLE, MEAN, AVERAGE, SUCCESS_RATE, STD_DEV, or WEIGHTED_AVG.

Snapshots are copies. Treat them as read-only and use actions for changes.

Namespaced storage

const count = await cmos.storage.get('count', 0);
await cmos.storage.set('count', count + 1);
await cmos.storage.remove('old-key');

Values must be structured-cloneable and JSON-compatible. Host storage is namespaced by plugin id and persists while disabled.

Widgets and declarative UI

Plugins never receive DOM nodes. A widget returns an allowlisted tree, and optional button actions are sent back to its worker callback. Text uses textContent; HTML, scripts, styles, URLs, arbitrary attributes, and DOM handlers are rejected.

cmos.registerWidget('counter', 'Counter', async () => {
  const count = await cmos.storage.get('count', 0);
  return {
    type: 'container', direction: 'column', align: 'center', gap: 'medium',
    children: [
      { type: 'text', text: `Count: ${count}`, size: 'large' },
      { type: 'button', text: 'Increment', action: 'increment', tone: 'accent' }
    ]
  };
}, async action => {
  if (action !== 'increment') return;
  const count = await cmos.storage.get('count', 0);
  await cmos.storage.set('count', count + 1);
  await cmos.refreshWidget('counter');
});

Nodes are strings, text, button, deviceButton, container, or spacer. deviceButton performs user-activated hardware pairing. Allowed tones: default, muted, accent, success, warning, danger. Sizes and gaps: small, medium, large.

Scramblers, renderers, and languages

cmos.registerScrambler({
  id: 'ru-training', name: 'R/U Training', category: 'Subsets',
  visualizer: '3x3x3', moves: ['R', "R'", 'U', "U'"],
  opposites: ["R R'", "U U'"], length: 20
});

cmos.registerScrambleRenderer('text-only', async scramble => ({
  type: 'text', text: scramble.join(' '), size: 'large'
}));

Scramblers are bounded data definitions, not host-executed generators. Also available: registerLanguage({ code, name, localizedNames?, translations? }) and registerTranslations(languageCode, dictionary). Registrations cannot replace built-ins or another plugin's ids.

Commands and bindings

cmos.registerCommand({ id: 'summary', name: 'Training summary',
  description: 'Show current ao12', defaultBinding: 'Alt+KeyS' }, async () => {
  const stats = await cmos.getStatistics({ type: 'AVERAGE', size: 12 });
  await cmos.toast(`ao12: ${stats.current ?? 'n/a'}`);
});

Commands appear in the palette under their lowercase id. Bindings use modifier names followed by KeyboardEvent.code. Reserved ids, built-in bindings, duplicate ids, and plugin binding conflicts are rejected. Bindings are ignored in inputs.

Mediated hardware

cmos.devices provides supports(kind), request(options), read(id, options?), write(id, bytes, options?), and close(id) for serial, hid, usb, and bluetooth. IDs are opaque and owner-scoped; devices close with the plugin. HID uses reportId, USB uses endpoint, and Bluetooth uses service/characteristic UUIDs.

cmos.registerWidget('pair', 'Controller', () => ({
  type: 'deviceButton', text: 'Pair serial timer', action: 'paired',
  request: { kind: 'serial', baudRate: 115200 }
}), async (action, device) => {
  if (action === 'paired') await cmos.storage.set('device', device);
});

Device selection usually requires a user gesture and secure context. API availability varies across browsers and WebViews. Always call supports and handle rejection.

Lifecycle and recovery

cmos.onCleanup(callback) releases worker resources such as timers or sockets when a plugin is disabled, removed, replaced, or rolled back. The worker is terminated afterward. Startup registrations commit transactionally.

Startup is limited to 30 seconds, callback invocation to 10 seconds, host RPC to 120 seconds, and cleanup grace to one second. Active device reads are cancelled after plugin cleanup and handles are then closed.

If edited source fails, CMOSTimer cleans partial work and tries the previous known-good source. The failed source remains available to repair.

Current limitations

  • Worker isolation does not universally remove worker network or local-storage-like APIs.
  • Permissions govern host RPC, not worker-local network access.
  • No package dependency resolver or remote marketplace.
  • Packages contain bundled JavaScript; compile TypeScript and dependencies first.
  • Events are not an animation-frame elapsed-time feed.
  • A restrictive CSP must explicitly allow the plugin worker and its dynamic compilation.
