Build on CMOSTimer

Plugins are JavaScript programs with a versioned cmos API. They can integrate timing hardware, react to solves, add dashboard widgets, define scramblers and visualizers, add languages, and store configuration.

Quick start

Open Settings → Plugins, add a plugin, paste code, and save it. Startup supports top-level await.

cmos.toast(`API ${cmos.apiVersion}`);

cmos.on('solveAdded', solve => {
  console.log('New solve', solve.time);
});

cmos.registerWidget('hello', 'Hello', container => {
  container.textContent = cmos.getState().currentSessionId;
  return () => container.replaceChildren();
});

Security model

Plugins are trusted, in-process code. They can access the DOM, network, and browser storage. Install only plugins you trust.

Registrations are transactional: CMOSTimer waits for startup and commits registrations together. Throws and rejected promises roll them back. Arbitrary side effects outside the API cannot be rolled back.

Versioning and packages

cmos.apiVersion reports the current semantic API version. A package declaring a newer required major is marked incompatible. The editor shows loading, active, fallback, error, and incompatible diagnostics.

Import/export uses .cmos-plugin.json. Imports are always disabled until reviewed.

{
  "format": "cmostimer-plugin",
  "formatVersion": 1,
  "plugin": {
    "id": "example.plugin",
    "name": "Example",
    "version": "1.0.0",
    "description": "Example integration",
    "apiVersion": "1.1.0",
    "code": "cmos.toast('Ready')",
    "enabled": false
  }
}

State

MethodResult
getState()A fresh snapshot containing sessions, normalized solves, settings, stats, goals, plugins, and current session id.
getTimerState()IDLE, INSPECTION, HOLDING, READY, RUNNING, STOPPED, LOCKED, or MANUAL_ENTRY.
getTimerElapsed()Current solve elapsed milliseconds while running, the stopped time while stopped, or zero otherwise.
getCurrentScramble()The relay-aware scramble as string[][].

Treat snapshots as read-only. Calls always delegate to the latest app state, including from long-running plugins.

Timer control

MethodBehavior
startInspection()Starts inspection from idle; throws if inspection is disabled or another timing state is active.
startTimer()Starts immediately, intended for hardware/controller integrations.
stopTimer(input?)Stops and stores a solve. Optional fields: time, inspectionTime, phases, penalty. Returns the solve id or null.
cancelTimer()Returns to idle without recording a solve.

Solves, scrambles, and sessions

  • addSolve(time, penalty?) adds a simple solve and returns its id.
  • addSolveWithDetails({ time, inspectionTime?, phases?, penalty? }) preserves inspection and split data.
  • updateSolve(id, updates) and deleteSolves(ids, sessionId?) modify stored results.
  • nextScramble() and previousScramble() navigate scramble history.
  • setCurrentSession(id) switches session and rejects unknown ids.
  • updateSettings(partial) shallow-merges application settings.

Events

cmos.on(name, callback) returns an unsubscribe function. Listeners are also removed automatically with their plugin.

Namespaced storage

const count = cmos.storage.get('count', 0);
cmos.storage.set('count', count + 1);
cmos.storage.remove('old-key');

Values must be JSON-serializable. Data is isolated by plugin id, persists when disabled, and is mirrored to native storage where available.

Widgets and render cleanup

registerWidget(id, name, render) receives a DOM container. Return cleanup from each render so remounts do not leak listeners or timers.

cmos.registerWidget('clock', 'Clock', container => {
  const interval = setInterval(() => {
    container.textContent = new Date().toLocaleTimeString();
  }, 1000);
  return () => clearInterval(interval);
});

Other extension points

  • registerScrambler({ id, name, category, visualizer, generate })
  • registerScrambleRenderer(type, render); render may return per-render cleanup
  • registerLanguage({ code, name, localizedNames?, translations? })
  • registerTranslations(languageCode, dictionary)
  • toast(message), await alert(message), and await prompt(message, default?)

Scrambler and language ids cannot replace built-ins or another plugin's registration.

Lifecycle and recovery

Use onCleanup(callback) for plugin-wide resources created at startup. It runs once when that startup is disabled, removed, replaced, or rolled back. Return cleanup from widget/renderer functions for resources belonging to a particular render.

If an edit fails, CMOSTimer cleans partial work and starts the previous known-good source. The editor reports fallback while retaining the broken source for repair.

Limitations

  • No sandbox, package dependency resolver, or remote marketplace.
  • Packages contain JavaScript; compile TypeScript first.
  • Events are not a high-frequency elapsed-time clock.
  • A startup promise that never settles blocks later plugin reloads.
